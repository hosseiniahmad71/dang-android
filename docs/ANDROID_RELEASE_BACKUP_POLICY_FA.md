## ۲. گیت غیرقابل عبور برای هر انتشار جدید
1. از آخرین نسخه اصلی branch `main` شروع کن. هیچ وقت کلید Release را دوباره تولید نکن. کلید اصلی موجود را از نسخهٔ پشتیبان خصوصی مالک بازیابی کن؛ آن را داخل مخزن، Issue، چت، Artifact یا log قرار نده.
2. شماره `versionCode` را **بیشتر از نسخه نصب‌شده** قرار بده؛ `versionName` را هماهنگ افزایش بده؛ شناسه و گواهی را ثابت نگه دار.
3. PR با آزمون‌های مالی، نسخه فایل پشتیبان، تست تمامیت و بررسی ثابت بودن شناسه/امضا باید موفق باشد. خروجی `CI-VALIDATION-ONLY-DO-NOT-INSTALL` هرگز برای نصب یا آپدیت تحویل نشود.
4. پس از ادغام و تأیید، چهار Secret مالک باید در GitHub Actions در مخزن موجود باشند: `DANG_KEYSTORE_BASE64`، `DANG_KEYSTORE_PASSWORD`، `DANG_KEY_ALIAS`، `DANG_KEY_PASSWORD`. فقط مالک حق وارد کردنشان را دارد.
5. Workflow `.github/workflows/release-production.yml` را **روی شاخه اصلی main** دستی اجرا کن. تنها `assembleRelease` با همان کلید مجاز است. گواهی APK جدید و قدیمی به اثر انگشت بالا پین می‌شود. اگر کلید/Secret یا گواهی صحیح نیست، **انتشار متوقف شود**؛ تولید خودکار یک کلید جدید ممنوع.
6. آزمون ارتقای واقعی با `adb install -r` باید از APK اصلی ۷.۳.۱ روی نسخه جدید اجرا شود، بدون uninstall/clear data. تطبیق کامل state، revision، ردیف‌های SQLite، محتوای مالی، قفل دوره‌ها و SHA-256 بک‌آپ‌های خصوصی قبل، بعد و پس از اجرای دوباره ضروری است.
7. فقط Artifact با عنوان `OWNER-SIGNED-VERIFIED-UPGRADE` پس از موفقیت تمامی مراحل، قابل معرفی به‌عنوان نسخه نصب‌شدنی است. SHA-256 فایل، نام نسخه، شناسه، fingerprint، شماره run و commit را در گزارش انتشار ثبت کن. به صرف build سبز ادعای نصب موفق روی گوشی مالک نکن.
8. تست روی گوشی واقعی و بازکردن حداقل دو صفحه مالی پس از نصب با داده واقعی کاربر، گیت پذیرش جداگانه است؛ بدون تأیید مالک کامل نشده.

## ۳. بک‌آپ بدون رمز و بازیابی
- فرمت جدید `.dangbak` یک JSON مستقل، نسخه‌دار با `format=dang-portable-backup`، `schema=3`، `version=1`، تاریخ، **کل Store** و SHA-256 canonical محتواست. **رمز و کلمه عبور ندارد**.
- فایل خارجی را با `ACTION_CREATE_DOCUMENT` در محل منتخب کاربر ذخیره کن؛ ذخیره‌سازی فقط در محل خصوصی اپ برای حفاظت از حذف/تعویض گوشی کافی نیست. فایل خارجی **متن ساده** است؛ نام اعضا، تراکنش‌ها و اقساط را می‌توان خواند. SHA-256 صرفاً تغییر ناخواسته را تشخیص می‌دهد و جلوی جعل عمدی را نمی‌گیرد. در فضای امن نگهداری شود.
- بک‌آپ داخلی: SQLite مستقل، snapshots خصوصی حداکثر ۶۰ نسخه؛ سیاست after-change، hourly-on-open، daily-on-open یا manual؛ هیچ یک بک‌آپ خارجی نیست.
- در بازیابی: ابتدا اندازه فایل، JSON و فرمت/نسخه، SHA-256، ساختار Store، invariants مالی و projection بررسی شود. خلاصه تعداد رخداد/قرارداد/عضو و موجودی به کاربر نمایش داده شود. تأیید جداگانه قبل از جایگزینی داده الزامی است؛ snapshot قبل از تغییر؛ transaction اتمیک؛ بازخوانی کامل SQLite و تطبیق digest بعد از بازیابی الزامی است. در شکست، موفقیت گزارش نشود.
- پشتیبان رمزدار قدیمی `dang-android-encrypted` با الگوریتم AES-256-GCM همچنان باید قابل ورود باشد؛ **رمز قدیمی فقط برای آن فایل قدیمی لازم است**. حذف سازگاری با نسخه قبلی ممنوع است.
- آزمون‌های لازم: بدون رمز roundtrip، tampering refusal، schema/version refusal، legacy password correct/incorrect، restore readback و سناریوی قطع/لغو عملیات، با دادهٔ ساختگی. بعد از تست CI روی Android باید تست واقعی SAF روی گوشی مالک هم انجام شود.
- تا زمانی که مسیر جدید روی دستگاه مالک تأیید نشده، نسخه قدیمی، دیتابیس و بک‌آپ‌های موجود را حذف نکن.
