# Dong / دُنگ — حسابداری مستقل خانوادگی

**نام تجاری انگلیسی: Dong** | **نام فارسی برنامه: دُنگ** | **نسخه مبنا: V1.0.0**.

> وضعیت فعلی: سورس V1 در شاخه توسعه ثبت شده؛ APK واقعی تنها پس از تأیید کلید اصلی و قبولی آزمون ارتقای امضاشده قابل انتشار است. فایل‌های CI که برچسب DO-NOT-INSTALL دارند، آپدیت کاربر نیستند.

## هویت ثابت اندروید
- `applicationId = ir.dang.household` — شناسهٔ فنی نصب قبلی و **نباید به ir.dong.household تغییر کند**؛ این تغییر نصب جداگانه می‌سازد.
- گواهی Release ثابت SHA-256: `2b468a624312d5db6028984714f8c9663f6873c87c9a950c5fe0fc6787416108`.
- نسخه اصلی قبلی: ۷.۳.۱ با `versionCode=14`. سورس ۷.۳.۲ کد ۱۵ تنها مرحله توسعه بود. **V1.0.0 = code 16**؛ نسخه‌های آینده باید versionCode بزرگ‌تر بگیرند.
- برای همه نسخه‌های واقعی یک کلید امضای خصوصی ثابت مالک استفاده شود؛ از کلید جدید یا Debug به عنوان آپدیت اصلی استفاده نکنید.

## بک‌آپ و بازیابی بدون رمز
- SQLite بومی آفلاین در فضای خصوصی برنامه، مستقل از حافظه مرورگر.
- پشتیبان داخلی محدود به ۶۰ snapshot؛ پس از تغییر، ساعتی، روزانه هنگام باز شدن برنامه یا دستی.
- خروجی خارجی جدید `.dangbak`: JSON قابل بازیابی، **بدون رمز** و با SHA-256 برای تشخیص خرابی تصادفی؛ محل ذخیره با Android Storage Access Framework انتخاب می‌شود.
- **هشدار محرمانگی:** فایل بدون رمز شامل اطلاعات مالی است. فقط در محل خصوصی و امن نگه دارید؛ SHA-256 از دستکاری عمدی جلوگیری نمی‌کند.
- فایل‌های رمزدار قدیمی همچنان با **رمز اصلی همان فایل** قابل ورود هستند و نباید امکان خواندن آن‌ها حذف شود.
- بازیابی شامل بررسی فرمت، صحت digest، اعتبار قواعد مالی، پیش‌نمایش، تأیید کاربر، snapshot قبل از جایگزینی، تراکنش SQLite و تطبیق مجدد داده خوانده‌شده است.

## ساخت و انتشار
- `.github/workflows/build-apk.yml`: بررسی CI با کلید موقت؛ **هیچ APK این Workflow برای نصب اصلی تحویل نشود**.
- `.github/workflows/release-production.yml`: تنها انتشار مجاز؛ خروجی Release با همان کلید اصلی، بررسی هویت/گواهی و تست واقعی `adb install -r` با پایگاه دادهٔ ساختگی از نسخهٔ قبلی.
- مالک باید کلید خصوصی قبلی را خارج از مخزن نگهداری کند و این چهار Secret را مستقیماً در تنظیمات امن GitHub وارد کند: `DANG_KEYSTORE_BASE64`, `DANG_KEYSTORE_PASSWORD`, `DANG_KEY_ALIAS`, `DANG_KEY_PASSWORD`. نام متغیرهای فنی قدیمی برای سازگاری Workflow ثابت می‌ماند؛ این نام‌ها نام تجاری محصول نیستند.
- گیت انتشار در صورت نبود کلید درست، تغییر Package، تغییر گواهی، عدم افزایش code یا عدم حفظ SQLite **Fail Closed** است.
- قواعد الزام‌آور در `AGENTS.md` و `docs/ANDROID_RELEASE_BACKUP_POLICY_FA.md` هستند.
